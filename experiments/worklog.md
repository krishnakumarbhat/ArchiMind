## Key Insights
- (setup) Baseline is linear RAG, not agentic: 3-node straight-edge graph, single-shot generation, no tools/validator/sandbox.
- (run 1) v0 on synthetic_bad_repo: harness_score=80.09 (validity 1.0, F1 0.68, dead 0.5, RAM 19.7MB). Regex edges already lose ~0.32 F1 vs AST truth — quantifies the CPG opportunity. Tiny-repo score is inflated; real repos (flask/requests) expected to drop F1 further and stress RAM.
- (run 1 caveat, discovered run 2) That 0.68 F1 is **not a quality signal**. v0's regex and the "ground truth" were the same blind technique on the same text; v0 has no caller/callee representation at all, so it was only ever scored in its own degenerate vocabulary.
- (model probe) Key valid (50 models listed). gemini-3.8-flash + 3.7-flash = persistent 503 (not provisioned for this key); gemini-2.5-flash = 404 (retired); text-embedding-004 = 404. Adopted: gen `gemini-3.1-flash-lite-preview` (repo default, generate OK), emb `gemini-embedding-001` (3072-dim, OK). Wired via gitignored `.env` only — never committed. Driver iterations should opportunistically re-probe `gemini-flash-latest`/3.8 and adopt if 200.
- (run 2) Potency re-ranking: **v1 (N2) has zero headroom** — v0 already scores `mermaid_validity_rate=1.0`, so reflection buys 0 of the 100 points and spends tokens. v2 (N3) was the only frontier node attacking the 50 points that are actually weak. N3 expanded; N2 left unexpanded with a recorded reason rather than quietly skipped.
- (run 2) A *second static parse is not an oracle*. Scoring an `ast`-based predictor against an `ast`-based truth returns 1.0 while both miss the identical edges. Any "CPG F1" number in this harness computed that way is unmeasurable by construction.
- (run 2) Dynamic oracle (`sys.settrace` + auto-harness) is the first independent ground truth here, and it immediately paid for itself by catching a real bug in my own CPG (eq. row 6: class-instantiation edges dispatched as `Cls.__init__`, not `Cls`) that no amount of static review had flagged.
- (run 2) One root cause explains every remaining weakness: **attribute-on-instance calls** (`self.s.query(uid)`). It caps `cpg_resolution_rate` at 0.5, `struct_recall_dyn` at 0.5, and drags `dead_code_acc` to 0.333. Fixing that one pattern is worth more than any remaining score-shaping.
- (run 2) Python 3.10 has no `code.co_qualname`, so a raw trace yields `fetch`, not `UserRepo.fetch`. Class identity has to be recovered from a code-object index built out of the repo's own modules, or the oracle and the CPG end up speaking different vocabularies and the comparison is meaningless.
- (run 2) `synthetic_bad_repo` has a **circular import** (repo→routes→repo) and cannot be imported at all, so it is unusable as a dynamic-oracle subject. Its `import routes` is also dead code — the fixture was hiding a finding. New acyclic `synthetic_cpg_repo` added; the old fixture is untouched so run-1 numbers stay comparable.

- (run 3) **A promotion that is provably precision-monotone on the trace it learned from is precision-DESTRUCTIVE on any independent trace.** Eq. row 8: the whole argument for edge promotion collapses if "observed" means "observed in the *training* trace". Measured: mode A holds precision 1.0 against its own fold and drops 0.6 -> 0.4286 against the held-out fold. This is the single most useful thing the loop learned, and it was only visible because the rule was *not* scored on the data it was fitted to.
- (run 3) Edge promotion (bind caller -> callee) and name promotion (bind bare callee name -> symbol) are not variants of one idea, they are different ideas with opposite behaviour. Edge promotion is **structurally incapable** of generalising: no rule is ever instantiated for a caller absent from the training fold, so held-out recall for unseen callers is 0 by construction (eq. row 9, confirmed empirically: 0.0). Name promotion transferred to callers that were never executed and moved unseen-caller recall 0.0 -> 0.2857.
- (run 3) The honest, decision-grade win: held-out recall **0.4286 -> 0.7143** at held-out precision **1.0** throughout, with the number of evaluation-confirmed edges rising 3 -> 5 and `cpg_resolution_rate` 0.4545 -> 0.6. Every promoted edge that the evaluation fold could check, it confirmed.
- (run 3) I found and fixed a bug in my own instrumentation mid-run: `split_caller_recall` was handed `promoted - cpg.call_edges`, which is always empty because promotion had already been applied. Every `recall_unseen_callers` was therefore pinned to 0.0 and mode B's generalisation was invisible until the subtraction was moved ahead of the apply. Caught only because the number was suspiciously round, not because a test failed.
- (run 3) A measured coverage ceiling beats a "needs more traces" hand-wave. A half-trace can only ever promote the half of unresolved call *names* it saw: ceiling **0.5** here (`commit`, `load` are fold-B-only). The deployment row, which sees all folds, promotes those two and drives the dead set down to exactly the one genuinely dead symbol — so the ceiling is the right thing to report, and it is a property of the trace budget, not of the rule.
- (run 3) **The standing metric misranks the better variant.** `harness_score` weights the structural term `30 * precision`, which is mathematically incapable of rewarding a recall gain, and charges every edge the evaluation fold could not re-exercise as a false positive. Result: mode B **loses** on the standing metric (66.23 vs 67.56) and **wins** on an F1 term (68.31 vs 64.56). The F1 number is reported alongside and deliberately *not* substituted -- swapping the metric mid-loop to make a variant look better is precisely the sin run 2 was convened to stop.
- (run 3) `dead_code_acc` is **not identified** under a held-out oracle: 0.0 strict for all three rows. Run 2 counted unexercised code as proven dead. The 20-point term needs to be gated behind the coverage bound before it can be believed at all.

Added `--pair` so v0 and v2 are scored on the same fixture by the same oracle. Added fixture `synthetic_cpg_repo` (acyclic; run-1 fixture left untouched).
- **Metric definition changed: `metric_def: dynamic-oracle-v1`. The 86.23 is NOT comparable to run 1's 80.09.** v2's structural term is oracle precision, v0's was static F1. The score column is only comparable within one definition.
- Reproducibility: v0 re-run on the run-1 fixture returns `structural_f1_static=0.6827`, `dead=0.5`, `blast=0.51ms` — identical to run 1. Score moves 80.09→80.06 only via `peak_ram_mb` (19.66→21.84MB, the two extra imported modules); RSS is process-wide and cumulative. Metric parity confirmed, not assumed.
- Head-to-head (the decision-grade result, same fixture, same oracle, same coarse vocabulary):
  - **v0 regex: coarse precision 0.2143** (3 of 14 predicted callees real)
  - **v2 CPG: coarse precision 1.0** (2 of 2 real), fine-grained precision 1.0, `struct_false_edges=[]`
  - v0 emits 14 candidate callees for 4 real ones; the CPG emits 2 and every one is real. A governance gate that invents a coupling is worse than a silent one.
- Where v2 is honestly worse: `struct_recall_dyn=0.5`, `cpg_resolution_rate=0.5`, `dead_code_acc=0.3333` (v0: 0.5). All one root cause — `self.s.query(uid)` attribute-on-instance calls are invisible to static resolution. The CPG flagged them in `cpg_unresolved`, which is the correct behaviour for a resolver that refuses to guess.
- Hard constraints: peak RSS 22.4MB (≤380 ✓), token cost $0.00 (no model in the loop ✓), no in-RAM vector DB ✓, no local LLM ✓, no clone ✓, secrets not committed (`.env` gitignored, verified) ✓.
- Toolchain: `ruff` clean, `mypy` clean, `flake8` clean; both modules ship an assert-based `_self_check()` that fails if resolution, dead-code, blast radius, SCC or the bitset/BFS closure cross-check regress.
- Insight: an *accuracy over a prediction set* (`dead_acc = |confirmed ∩ predicted|/|predicted|`) is the only dead-code metric that does not reward guessing "everything is dead". Reporting 0.3333 against v0's hardcoded 0.5 is the honest trade, and it is what makes the recall number trustworthy.
- Next: v3 trace-informed edge promotion — use the oracle's missed set to promote statically-unresolved attribute-on-instance edges, then re-measure. This is the highest-potential node; 30 pts of F1 are gated behind it.

### Run 3: v3 trace-informed edge promotion under a two-fold held-out protocol — REGRESSION on the standing metric, real generalisation underneath (keep, METRIC CORRECTION)
- Timestamp: 2026-09-26 | Evidence: `experiments/run-3.log` | Code: `src/02_trace_promote.py` (new), `src/01_dyn_oracle.py` (per-target dispatch attribution), `src/00_cpg_static.py` (`unresolved_calls` with caller scope), fixture `synthetic_promo_repo`
- **Metric definition changed: `metric_def: dynamic-oracle-heldout-v2`. NOT comparable to run 1 or run 2.** The rule is learned from fold A only and every number is scored against fold B only. Neither the artifact nor its score has seen the evaluation fold.
- **Parity first, always.** I modified the oracle (per-target attribution) and the CPG (new `unresolved_calls` field) before measuring anything, so v2 was re-run: `synthetic_cpg_repo` returns **86.23, prec 1.0, rec 0.5, dead 0.3333, coarse_v0 0.2143, coarse_cpg 1.0, `struct_false_edges=[]`** — bit-identical to run 2. Metric parity confirmed by re-measurement, not assumed.
- The fixture is built so the folds cannot cheat: every entry point lives in its own module so `fold_targets(2)` splits them two-and-two, and fold B ends up with **0 dispatches from callers seen in fold A and 7 from unseen callers**.
- Paired rows, same fold, same oracle (`synthetic_promo_repo`):
  | | promoted | prec | recall | F1 | unseen-caller recall | held-out prec | dead strict | resolution | score | score_F1 |
  |---|---|---|---|---|---|---|---|---|---|---|
  | static control | 0 | 0.6 | 0.4286 | 0.5 | 0.0 | 1.0 | 0.0 | 0.4545 | **67.56** | 64.56 |
  | mode A (edge) | 2 | 0.4286 | 0.4286 | 0.4286 | **0.0** | 1.0 | 0.0 | 0.5385 | **62.42** | 62.42 |
  | mode B (name) | 4 | 0.5556 | **0.7143** | **0.625** | **0.2857** | 1.0 | 0.0 | **0.6** | 66.23 | **68.31** |
- **The headline is a negative result and it is the useful one:** mode A *lowers* the score by 5.14 pts. It is precision-monotone on the fold it was trained on and precision-destructive on the fold it was not. Anyone reporting trace-informed promotion against the trace it learned from would have measured 1.0 precision and concluded the opposite.
- What is genuinely new underneath: mode B is the only row that moves **unseen-caller** recall (0 -> 0.2857), it does so without spending a single false edge (held-out precision 1.0, confirmed-edge count 3 -> 5), and it is a *transfer* of a rule to code that was never executed. That is the only claim here that survives the held-out protocol.
- Deployment shape, reported and explicitly **excluded from the ranking** because its precision is 1.0 by construction: 6 promoted edges, 11 total, resolution 0.6471, predicted-dead reduced to exactly {`cache.Cache.stale`} — the one genuinely dead symbol in the fixture. This is what ships; the held-out numbers are what *license* it.
- Coverage ceiling 0.5: `commit` and `load` are reachable only from fold B, so a fold-A-trained rule cannot touch them. The deployment row can, which is exactly why the ceiling is a trace-budget property.
- Ablation `v3` on `synthetic_cpg_repo` returned **`status: unvalidated`** — fold B held a single target (`routes.get_session`) that dispatches nothing, so the protocol is undefined. Reported as unvalidated rather than backfilled with a 0.0. (1 unvalidated this segment; the loop caps it at 1.)
- Hard constraints: peak RSS ~23MB (<=380), token cost $0.00, no in-RAM vector DB, no local LLM, no clone, `.env` gitignored. `ruff` clean, `mypy` clean, project `flake8` gate (E9,F63,F7,F82) clean. All three modules ship assert-based `_self_check()`s; `src/02_trace_promote.py` asserts the mode-A/mode-B asymmetry *and* the collision guard.
- Novelty: **58/100 -> engineering track, no LaTeX paper.** The *mechanism* is incremental and I found the prior art myself: Nier et al. (FSE 2025) already improves static call graphs from runtime data but only by seeding entry points and lists edge-quality analysis as future work; Chakraborty et al. (ECOOP 2022) root-cause missing static edges from dynamic traces; PhaseSeed (arXiv:2511.06661) names my exact failure mode -- "functions can be re-invoked from calling contexts unseen during the training phase" -- and resolves it by architectural argument, never by measuring it; GRAPHIA (CISPA 2026) ranks candidate callees per unresolved site with no generalisation test. What is not in any of them is the two-fold held-out protocol and the finding that in-sample promotion measurement inverts the sign of the result.
- Next: the metric fix is the highest-value node, not another variation -- `dead_code_acc` is unidentified (20 pts) and the structural term is precision-only (30 pts misranked). Re-measure runs 1-3 under a corrected `metric_def` in a dedicated iteration rather than retrofitting it here.
